# Campaign: incremental, reproducible Player builds

## Status

Goal: make native dependency reuse correct and make everyday builds measurably faster without changing artifact contracts. Baseline revision: `1a31a38b04674cc022117138563a6f50eb1d664b`. Accepted: B0, clean-prefix, bottle-reinstall, bundling and rpath fixes, default Linux-to-macOS runtime-layout switching, libplacebo Python input isolation, rust-fontconfig source-writer serialization, CI cache-key correction, O1 investigation, and O2 shell. The layout switch recognizes only the default Linux runtime sources and fails safely for other existing directories. C1 is parked at `campaign/build-cache` (`01ebc0c`): a fresh direct Cargo build can skip native validation, while forcing validation through Cargo rebuilds dependents. On 2026-11-10 the owner authorized requiring the kache Cargo shim and co-developing their kache fork. Use that shim as the Cargo reader boundary, and validate and hold the generation for the full build. Unshimmed or absolute-path Cargo invocations are outside that validated contract. The local `campaign/build-cache-shim` prototype and kache fork branch `campaign/player-native-guard` guard tested external Cargo aliases as well as direct invocations; configured aliases on Cargo older than 1.94 fail closed. Prototype `c2efb84` also pins the native generation with a directory descriptor, preventing tested Cargo metadata and forced-environment overrides from redirecting consumers. It reserves descriptor 198 and fails if that descriptor already belongs to another object. Its macOS release acceptance and emulated Linux release audit passed; size and 1080p memory were measured on both. Meson also searches for optional system packages: the prototype detects Linux pkg-config metadata changes, but does not fully track CMake discovery or optional library and header contents. On macOS, actual libplacebo Meson setups found `libxxhash` through CMake while pkg-config could not; changing the CMake package changed the generated include directory while the prototype accepted the old identity. Ordinary Meson reconfiguration retained the old result; `--clearcache` reconfiguration detected the change. The prototype also accepted a fresh Cargo build after a module changed at the same `PYTHONPATH`, even though libplacebo's real generator loaded the changed module. Accepted fix `d098a5f` isolates the libplacebo generators from that path and Python's user site while preserving the Meson frontend's environment; real macOS and emulated Linux builds succeeded with a conflicting Jinja module and a frontend requiring `PYTHONPATH`. Prototype `5dc2d67` also fingerprints the generator patch. System Python packages, the frontend's own Python inputs and other toolchain inputs remain unqualified. Accepted fixes `2bccc48` and `86d4869` serialize rust-fontconfig writers sharing a source directory or installation prefix, including writers from separate checkouts. Tests cover same-prefix reuse, killed writers, overlapping paths and crossed lock order. Cargo readers are not covered by the main checkout’s writer locks. The original Linux rust-fontconfig helper accepted a copied prefix after both its header and shared library were corrupted. Prototype `ce088b8` locks and validates the selected managed prefix through guarded Cargo, including a missing prefix and failed installation; an actual kache-shimmed Cargo invocation rejected a corrupted copied header. A local emulated Linux release and its closure audit passed. Prototype `8e0cbc7` orders writer locks for shared, identical and crossed paths and rejects a lock path replaced while waiting; it also avoids a reproduced deadlock between nested writers and path traversal. Prototype `9f1b332` covers the reproduced `PKG_CONFIG_PATH` race and tests higher-priority, symlinked, relative and library-only pkg-config paths. A controlled consumer using `RUSTFLAGS=-Lnative=…` still allowed its managed library to be replaced during Cargo; a separate real Cargo probe linked with that flag and failed without it. Mainline `9beccc2` validates the owned rust-fontconfig products before reuse and rejects unmarked custom products; `15910fc` rejects non-UTF-8 link text. Candidate `a83364a` incorporates those checks and passed its cache suite and emulated Linux release audit. Mainline `5d6ac53` preserves required flags when Cargo encoded flags are set and records their effective value in the rust-fontconfig identity; candidate `a0d5907` carries that fix through nested guarded builds. Other compiler and pkg-config discovery paths and complete toolchain identities remain unqualified. The fork needs a provisioned version in CI. C1 remains unaccepted while those boundaries and the remaining qualification are unresolved. C2 remains incomplete until C1 validates restored products. The owner waived performance gates on 2026-11-10; see the benchmark report for measurements and host-load limits. F1 remains incomplete.

The linker-path probe also confirmed that Cargo's `[build] rustflags` can select the managed library, that `RUSTFLAGS` overrides that configuration, and that `CARGO_ENCODED_RUSTFLAGS` overrides `RUSTFLAGS` even when empty. A guard that parses only one environment variable would therefore leave the same race reachable through other effective flags. Any fix must cover the flags Cargo actually uses, preserve their precedence, and account for a fresh Cargo build that may not invoke rustc at all.

In the pinned Cargo, a full `cargo config get --format json` omitted an environment-defined `CARGO_TARGET_X86_64_UNKNOWN_LINUX_MUSL_RUSTFLAGS`, while querying the target-specific key returned it. A full configuration dump alone is therefore not an exhaustive source of linker paths.

## Decisions

- **Owner:** Preserve Cargo, Muon/Meson, Samurai/Ninja, pinned FFmpeg producer contracts, native Apple compiler and SDK, Alpine musl target, signing, audits, playback gates, artifact names and checksums. No Buck2, Bazel, derivation migration, remote cache, new service, glibc, libgcc runtime, or opportunistic upgrades. The owner authorized co-developing `~/d/kache` for this campaign; other repositories remain out of scope. Nix is optional and must not be a runtime or build prerequisite. No production release.
- **Prescribed:** Build identity is not artifact integrity. Validate the full owned output set, including paths, file content and symlink targets, on every reuse, including restored CI caches. Reject unexpected owned outputs and collisions. Do not trust old stamps; migrate by rebuilding into a clean, isolated prefix. A process-safe lock must cover validation, building and publication, recover automatically after process death, and serialize concurrent writers. Readers must see one complete, validated generation for the duration of a build or fail before consuming it: cover `scripts/build.sh`, `scripts/build-linux.sh`, both release scripts, the bundler, and Cargo builds/tests through the required kache Cargo shim, including concurrent publication. Do not rely on a one-time Cargo build-script check that can be skipped on a fresh build. Never remove another component's products or mutate a generation in use. Use immutable component staging and an atomically published generation if needed; preserve the existing prefix path and consumer-visible layout. If the full reader guarantee cannot be met, park the slice rather than claim concurrency safety. Integrity metadata is authorized here because it serves this concrete failure mode; do not build a generic artifact store.
- **Prescribed:** Fingerprint relevant component recipe, source and checksum, patches, effective tools and versions, compiler/linker flags, target and ABI, deployment target, relevant environment and actual dependency identities. Separate recipe inputs so unrelated edits do not invalidate everything; do not hash entire build scripts. Include absolute prefix where embedded paths affect outputs. If dependency edges cannot be demonstrated, use a conservative edge until proven unnecessary. Keep one authoritative component graph and recipe per target, with explicit staging, validated and published states. Encode metadata deterministically with a version; reject unknown versions, malformed entries, duplicate ownership, unsafe paths and incomplete state, then rebuild or fail with component and cause. Resolve allowed symlinks without leaving the cache root. Never infer a valid artifact from a success marker alone.
- **Prescribed:** CI workflow edits are authorized only to converge the named build and cache entrypoints and retain all existing gates. Cache key matches and restore-keys never bypass validation. Existing FFmpeg runtime and SDK fetchers retain ownership and verification; do not fold them into a new cache.
- **Delegated:** Choose the smallest implementation supported by the adversarial tests. Choose a pinned Nix tool set only if it works on an available supported host without replacing Apple tools or the Alpine build; otherwise omit the shell and record the specific blocker. Keep the Muon/libplacebo fallback unless independently validated on both targets. The Nix and sccache experiments may install local tools but cannot change production flags, linkage or outputs. No experiment may add a daemon or service, including a compiler-cache server; if sccache requires one, record that incompatibility and omit the pilot and integration rather than violate the owner constraint. Any dependency must fit the existing build-time, binary-size, startup and runtime gates; where no numeric gate exists, measure and report build-time and binary-size impact. Retain sccache only if representative edit/rebuild median benefit exceeds observed spread and configuration cost is justified. Keep its directory configurable and bounded if retained.
- **Prescribed:** Intentional contract changes are limited to cache state, invalidation and failure behavior, diagnostic output, and optional developer tooling. Document any new cache paths, locking and supported environment variables with tests. Do not change public player APIs, ABI, runtime behavior, permissions, or release artifact identities.

## Baseline

At preflight, no Player build or acceptance suite was run and no existing Player failures were established. Syntax checking the five named shell scripts took 0.02 s wall on this macOS arm64 host; this is a loop check, not a performance baseline. Neither native prefix had a libplacebo stamp; Docker reports a running Linux arm64 engine; the required x86-64 container build remains unverified. Nix and sccache were not found on PATH. A probe of each script’s actual `have` function accepted a matching stamp with its product missing. An unchanged Linux build-script probe with stubbed external commands reached Cargo with an arbitrary libplacebo stamp and no libraries. A separate macOS probe used Homebrew Meson and Ninja to install a small real C library through `DESTDIR`, then consumed it through a symlinked final prefix with pkg-config, Apple Clang and a running executable. This proves the staging mechanism can preserve prefix references for that case, not that libplacebo, Cargo or concurrent readers are safe; C1 must prove those. The default `meson` on this host reports oxidized-meson 1.7.0 and its generated Ninja file lacked an install target in that probe; use the proven Homebrew frontend for the probe and record the selected actual frontend when establishing the build baseline. Use the original revision in a separate worktree as the runnable reference. Preserve existing local caches and user data; never clear an existing shared prefix to manufacture a cold run.

## Acceptance

`tests/build-cache.sh` must show: (1) identical input causes zero builds or installs; (2) an independent change leaves unrelated components untouched; (3) a patch change rebuilds exactly its component and actual dependents; (4) changed compiler and linker flags reject incompatible reuse; (5) target and ABI cannot cross-reuse; (6) missing, modified, extra or corrupted outputs rebuild or fail safely; (7) install failure publishes no success; (8) interruption never accepts partial products; (9) changed dependencies cannot leave stale products satisfying the graph; (10) simultaneous writers and readers, including a direct Cargo invocation and both release entrypoints, see one coherent generation or fail safely. Include a killed lock holder and a killed publisher followed by recovery, permissions and symlinks, path collisions, restored caches, old stamps and dependency version removal. Verify safe handling of non-UTF-8 and traversal paths, symlink escape and special files: reject unsupported cases without modifying anything outside the cache. Check expected outputs independently of a mutable manifest, and reject unowned stale prefix products. Cache integrity checks address accidental corruption; they do not authenticate a malicious cache containing forged metadata. Demonstrate that breaking validation makes the relevant test fail. The synthetic harness proves the cache mechanics, not real native compatibility.

For parity, compare the reference and candidate entrypoints on the same corpus: command success and failure, effective flags and backends, installed paths, linkage, SDK/runtime consumers, release packaging, and supported environment overrides. Normalize only nondeterminism actually observed. Each reference behavior gets a focused case or a named environment-dependent proof. Compare two independent builds per available platform under the same pinned environment and report differences in artifact bytes and contents, normalized only for demonstrated nondeterminism. The application and both release artifacts must retain existing audits, signing, runtime closure and playback acceptance; identical bytes are not assumed where existing build metadata is nondeterministic. Reproducibility claims must state what was compared and what was normalized.

## Reference and boundaries

The macOS script currently copies Vulkan-Headers; installs checksum-pinned Vulkan loader and shaderc bottles; builds SPIRV-Cross; builds patched libplacebo with the Vulkan registry and shaderc; and installs prebuilt MoltenVK. The Linux script installs Vulkan-Headers and a pinned shaderc archive and builds static libplacebo; Vulkan loader comes from Alpine, and rust-fontconfig has a separate build script. The libplacebo source bundle includes fast_float, glad, Jinja and MarkupSafe. Confirm all edges and indirect outputs in B0, including the Metal patch's SPIRV-Cross use; ordering alone is not an edge. Both scripts currently stamp a global hash; Linux also clears its prefix when it changes. `scripts/build-linux.sh` currently tests only for `.stamp-libplacebo`; `crates/player-output/build.rs` reads macOS pkg-config files and Linux libraries directly, and `scripts/bundle.py` resolves libraries from the macOS prefix. Direct Cargo use and these consumers must be traced and exercised before publication design is accepted. `scripts/dev-deps.sh` pins local tool versions, whereas macOS CI currently uses `brew install` without those checks.

All scratch, worktrees and disposable benchmark state live under `.work/`; ensure `.work/` is in `.git/info/exclude` before writing there. Do not touch existing caches or user files destructively.
